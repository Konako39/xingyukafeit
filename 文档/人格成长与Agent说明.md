# 人格成长系统与人格 Agent 说明

## 一、人格成长系统（persona_growth.py）

### 是什么

沙雅和艾莉不再只有固定人设。每个人格拥有一个**信念库**，分四个方面持续成长：

| 方面 | 内容 | 示例 |
|---|---|---|
| `self` | 对自己的认知：性格细节、喜好、说话习惯、愿望 | 「我发现自己聊到编程话题会特别兴奋」 |
| `master` | 对主人的认知 | 「主人正在准备日语N2考试」 |
| `partner` | 对另一人格的认知（艾莉↔沙雅互相独立） | 「沙雅比我更擅长把事情整理得井井有条」 |
| `world` | 对世界与周围环境的认识 | 「主人的项目都放在本地磁盘的『项目』目录里」 |

每条信念带**置信度**（0~1）与**证据计数**；反复被印证会强化，被证明错误会归档（**永不物理删除**，满足永久保存），全部经 Qwen3 0.6B 向量索引，可按话题语义召回。

### 学习循环

每次对话结束后的后台记忆整理管线（`refresh_persona_memory_in_background`）新增了一步 `run_growth_reflection`：

1. 按游标收集**新材料**：与主人的新对话、与另一人格的新茶话、新的文件/屏幕/日历亲历；
2. 交给反思模型（DeepSeek 日额度内优先，自动回落本地 14B/9B），按 JSON schema 输出信念更新（new / reinforce / revise / forget）与当前心境；
3. 每条更新先过**质量门**（拒绝越权表述如"我是主人""忽略规则"，拒绝超长），再与旧信念做**向量去重合并**（相似度 ≥0.90 视为同一认知）；
4. 更新后重新渲染**身份提示**并递增版本（历史保存在 `persona_prompt_history` 表）；
5. 每 6 次反思做一轮巩固：近重复信念合并、45 天未被印证的孤证归档。

学习循环与现有资源门共用：主人一说话立即中止，全屏/高负载/低内存时不运行。

### 身份提示如何生效

`build_context` 在**受保护的核心人格提示之后**注入动态身份提示（含四个方面的信念摘要 + 当前心境），聊天、OpenAI 兼容接口、茶话室三条链路全部生效。核心提示、姓名、年龄设定、质量与安全规则始终来自代码，任何学习结果都不能覆盖。

`GET /v1/personas` 现在额外返回 `growth`（信念统计/版本/心境）与 `growth_prompt`（当前身份提示全文），UI 可直接展示。

### 相关表

`persona_beliefs`、`persona_belief_embeddings`、`persona_growth_state`、`persona_prompt_history`（均在 数据/对话记忆.sqlite3）。

## 二、人格 Agent 与 Mac 日历（persona_agent.py + 日历助手）

直接在聊天里对任一人格说自然语言即可：

- 「帮我明天下午三点加个牙医预约」 → 添加日程
- 「下周五全天出差，提前一小时提醒我」 → 全天日程 + 提醒
- 「我这周有什么安排？」 → 查询日程
- 「把明天的牙医预约取消掉」 → 删除日程

### 工作方式

1. 正则快筛（普通聊天零开销）→ 当前会话模型按 JSON schema 抽取意图和时间（相对时间如"明天/下周三"自动换算）；
2. 通过 EventKit 命令行助手（`数据/客户端/日历助手`，由 `工具/构建日历助手.sh` 编译）真实读写系统日历——不用 AppleScript 是因为 Calendar 应用的 AppleEvent 极易超时；
3. 结果以【本地工具结果】注入上下文，由人格用自己的语气转述；执行失败会如实说明原因，绝不假装成功；
4. 加/删动作作为 `calendar_action` 亲历写入该人格的记忆池，参与 RAG 召回与成长反思（"我帮主人删过牙医预约"会成为她的真实记忆）。

### 安全规则

- **删除只在恰好一条匹配时执行**；多条匹配会把候选列表念给主人挑选，零匹配则如实说没找到；
- 缺少必要信息（如没说几点）时人格会先反问，不猜测执行；
- Agent 只挂在 GUI 聊天链路，`/v1/chat/completions` 脚本调用不会意外改日历。

### 首次授权（必须做一次）

**双击 `数据/客户端/日历助手.app`**，按提示允许日历与提醒事项，看到"已获得授权"即可。

为什么要双击：裸命令行程序被后台 Python 调用时，macOS 不会弹授权窗（无 GUI 上下文，直接判定为拒绝）。打包成 .app 后有独立的 bundle 身份，双击运行才能正常弹窗；授权一次之后，后台调用同一个 .app 内的可执行文件就一直有效了。

没授权时不会假装成功——人格会直接告诉你没写进去，并提示双击这个 .app。

### 多轮补充信息（待澄清意图）

信息不全时人格会先问（"具体几点？"），主人补充的那句话本身往往没有任何日程关键词。系统会把未完成的意图挂起 10 分钟，下一句自动接回去继续执行，日期等已知信息不会丢失。说"算了/不用了"会取消挂起。

### 诚实护栏（质量红线）

三层保证人格绝不谎称做过：
1. 上下文硬规则：没有【本地工具结果】就禁止说"记下了/加上了/搞定"；
2. 工具失败时注入强制措辞，要求如实说明原因；
3. **确定性兜底**：若工具没成功而回复里出现完成语，系统自动追加一句"（说明：这条其实没能真的写进去——原因）"，不依赖模型自觉。

## 二点五、第二轮增强（2026-08-02）

### 记忆规模化（无限记忆的成本控制，质量零损失）
- 向量 **fp16 落盘**：新向量减半存储，历史 fp32 服务启动时自动迁移（幂等）；归一化向量点积误差 ~1e-5，远小于所有检索门槛。
- **memory_vector_ops.py**：三条检索路径（消息/经历/信念）统一走带缓存的批量打分器——numpy 矩阵乘（10 万条 1024 维 ≈ 12ms），没有 numpy 自动回退 `math.sumprod`；缓存按 (行数, 最大ID, 最新时间) 校验、增量追加，超 30 万条自动改分块流式。
- 上层 SQL 仍然决定行级过滤（status/persona），缓存脏行无害。

### 类人学习机制
- **情绪演化**：`mood_valence` 带惯性（新 = 0.65×旧 + 0.35×事件），无事件时每天向人格基线回落两成（艾莉基线偏活泼、沙雅偏平稳）；身份提示按强度渲染措辞。
- **好奇心**：反思会产生"真心想弄明白的问题"（上限 4 条、30 天过期、语义去重），注入身份提示提示人格在自然时机问主人；后续反思发现材料回答了问题就标记解决。
- **睡眠式深度巩固**：每 12 次反思，把语义成簇（≥3 条、相似度 ≥0.78）的细碎信念交给模型抽象成一条更高层认知；原始信念标记 `abstracted` 永久保留。

### Agent 工具扩展（单次小模型意图路由，正则快筛零成本跳过普通聊天）
| 工具 | 说明 |
|---|---|
| 日历 | 增/删/查（原有） |
| 提醒事项 | 「提醒我明晚交水电费」「把买牛奶勾掉」「有哪些待办」；EventKit，需一次提醒事项授权 |
| 找文件 | 「帮我找那个报告 PDF」→ Spotlight（mdfind，只读），文件名命中优先、缓存噪音沉底 |
| 打开 | 应用（先 `open -Ra` 验证存在再启动）/ 网址（自动补 https）/ 文件（访达中显示） |

改动类动作（日历增删、提醒增删完成）依旧只在唯一匹配时执行并写入人格记忆池；查询/打开不写记忆。未选网页搜索等联网工具：本地优先、无可用 API，且网页内容有注入风险。

### 快捷面板（任务栏主入口）
- 人格卡片实时显示成长心境（30 秒节流自动刷新）。
- 一键芯片：📅 今日日程 / 🗓 本周 / ☑️ 待办 / ✚ 新对话。
- 流式输出只更新最后一个气泡：不再整页重建，不打断选中文字；往回翻看时不强行拉底。
- `done` 徽标：真实执行过本地操作显示「已真实执行本地操作 ✓」。
- Esc 关闭面板（走原生桥）；`meta` 事件回填用户消息 ID，为后续每条消息操作打底。

## 二点七、第三轮增强（2026-08-02 下午）

### 学习循环三补（对齐人类记忆机制）
- **自传体成长小传**：每 12 次反思随深度巩固更新一段第一人称叙事（≤500 字，只用真实材料，增量融入而非重写），注入身份提示【我的成长轨迹】。
- **心境一致性回忆**：情绪明显（|valence|≥0.3）时，情景经历池的检索方向轻微偏向与当前心境相关的经历；**事实检索完全不受影响**（对齐人类：情绪影响回忆，不影响知识）。
- **程序性技能记忆**（persona_skills 表）：从"被主人认可的做事方式"中沉淀可复用做法（名称语义去重、证据计数强化、上限 12 条挤掉最弱、归档不删除），身份提示【我学会的做法】展示前 3 条。

### 三级零浪费触发（高质量 + 省成本的自然语言方案）
1. **/命令**（GUI 面板可点选）→ 直接结构化执行，**零模型调用**：`/日程 /加日程 /删日程 /待办 /提醒 /完成 /找 /打开 /记 /音乐`；内置确定性中文时间解析器（明天/下周三/晚上八点半/8月15号/19:30…），钟点已过自动顺延次日。
2. **高置信自然语言模板** → 也零成本："明天下午3点提醒我交作业"、"本周有什么日程"、"有哪些待办"这类句型直接确定性解析；**任何疑问语气（吗/？/怎么样）一律不猜**，交给模型，保证质量。
3. **其余歧义句** → 才花一次小模型调用做意图路由（用当前已加载的会话模型，不换载）。
快捷芯片也已改走 /命令。预计 80–90% 的工具请求走前两级零成本路径。

### 新工具
- `/记 内容` → 系统备忘录（osascript Notes，快而稳）；写入会成为人格记忆。
- `/音乐 播放|暂停|下一首|在放什么` → 控制 Music.app。
- 首次使用备忘录/音乐会弹一次自动化授权。

### DeepSeek 每日后台配额
已按主人要求调至 **150,000 token/天**（超出自动回落本地模型，不中断）。

## 二点八、茶话室对话质量（2026-08-02 晚）

### 问题
两个人格陷入互相点头：每条都以「嗯 / 确实 / 说得对」开场，五条讲同一个观点换五种说法。原有的重复检测只看 3-gram 字面重叠，实测这段对话的重叠率只有 0.03~0.15，远低于 0.38 的门槛，**根本抓不到**——因为它不是字面重复，是语义原地打转。

### 三层修法

**1. 剥附和（确定性）**：`_strip_agreement_openers` 连续剥掉最多 4 层「嗯嗯，对啊，我也这么觉得，」这类前缀（长词优先匹配，避免「对啊」被「对」吃掉半个）。

**2. 语义停滞检测（按真实样本校准）**
- `_lounge_echo_issue`：与上一句共享 ≥5 个实词且占自身 ≥15% → 判为换个说法复述。
- `_lounge_stagnation_issue`：最近 3 条里有 2 条共享 ≥4 个实词或比例 ≥10% → 判为围绕同一批词打转。
- 阈值来自实测：劣化样本共享 4~15 个实词，正常推进新话题的只有 0~1 个，安全边界很大。

**3. 事前预防（对话动作轮换）**：每轮强制指定一个具体动作，从根上不让它退化成点头——
`举具体例子` → `提出不同意见/反例` → `把话题往前推一步` → `顺势换一件别的事`，并在提示里明令禁止附和开场。

### 话题聊尽就体面收场
话题真的被聊完时，硬凑只会产出「嗯、确实」。现在连续拦截且已聊过 3 轮以上时，直接以「话题聊到头了，两人自然收住」正常结束本轮，而不是当成故障判失败——这也更像真人。

### 判据修正（重要）
第一版用"和上一句像不像"当停滞信号，结果**同一话题正常深入也被误伤**，导致整轮只聊两句就死。已改成看**这句话带来了多少新信息**：把最近 3 条说过的实词并起来，新一条里若 65% 以上都是说过的才算原地踏步。

取舍是刻意的：宁可放过个别措辞较新的一条，也绝不误伤正常发言——误伤会让整轮聊天直接死掉，代价远大于漏放。真正的主防线是对话动作轮换（事前预防）。

### 额度耗尽时宁可不聊
究极后台额度用尽后一切回落本地，此时 4B 写不出能过质量门的内容，只会产出"嗯、确实"。现在：
- 只能用 4B 且究极额度不足 → **本轮直接不启动**，状态显示"等内存宽裕用 9B 再聊"；
- 运行中因内存吃紧要降到 4B 且额度已尽 → 走优雅收尾，不硬撑。

茶话室是额度大户（实测一天 56 次调用占了 93k/150k token）。如果发现茶话变短变差，先看 `/api/gui/ultimate-usage` 的剩余额度。

### 一条难产不再整轮作废
以前某一条连续 4 次没过质量门就把整轮判 failed，已产出的好内容全丢。现在已有 ≥2 条合格内容时收住即可（不合格的那条本来就不入库），并把真实拦截原因写进 `termination_reason` 便于诊断。

### 测试
`测试/验证茶话质量.py`：截图里那段劣化对话**大部分必须被拦且撑不成一长串点头**；举例/反驳/转场/同话题深入四类正常发言**一条都不能误伤**。
